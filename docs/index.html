AI Development Playbook

A GitHub-native governance and information-integrity layer for reliable, long-running AI coding with ChatGPT, Codex, and other coding agents.

It is designed for projects that need durable repository memory, explicit agent authority, bounded context retrieval, evidence-aware validation, and cost-aware task routing across sessions.

Open the GitHub repository 5-minute quick start

When this playbook is a good fit

Multi-session AI coding

Work continues across chats or agents and stale context must not silently become project truth.

ChatGPT + Codex workflows

You want clear separation between planning, implementation authority, execution capability, and validation evidence.

Repository memory

GitHub should remain the durable source of truth instead of relying on one conversation's memory.

Context engineering

Agents should load only the minimum canonical information required for the current task.

Agent governance

You need explicit boundaries for who may read, write, execute, validate, deploy, or stop.

Evidence integrity

Software PASS, hardware evidence, production state, and unverified assumptions must stay distinguishable.

Probably unnecessary when

  • You are writing a one-off script or a short single-session prototype.
  • Your repository already has an equivalent, explicit AI-governance and durable-context architecture.
  • You do not need cross-session continuity, agent handoffs, or evidence-sensitive validation.

What it helps organize

Context engineering · AI coding agent governance · ChatGPT and Codex collaboration · repository memory · task routing · permission and authority boundaries · validation evidence · debugging discipline · cost-aware model use.

The Playbook exposes two user-selectable project AI modes, ChatGPT-Only and ChatGPT+Codex. The adopting project's own governance remains higher authority and narrows the actual path/action permissions inside the selected mode.

Public adoption example

masini1491/esp32-vag-data-server publicly declares this Playbook as its common development baseline in its project governance. This is a first-party adoption example, not a third-party endorsement.

繁體中文摘要

AI Development Playbook 是一套以 GitHub 為持久專案記憶與事實來源的 AI 協作開發治理層， 適合跨聊天室、跨代理、長期演進的開發工作。它聚焦於 context engineering、agent governance、 任務路由、權限邊界、驗證證據與成本控制，而不是增加更多提示詞儀式。

如果你的專案需要 ChatGPT／Codex 長期協作、避免舊 context 冒充 current truth， 或希望 AI 只讀本次任務最低必要的權威資訊，這套 Playbook 才較有價值。 一次性腳本或短期 prototype 通常不需要這麼完整的治理。

公開採用案例：masini1491/esp32-vag-data-server 已在自身 governance 中明確宣告採用本 Playbook。這是作者自己的實際採用案例，不是第三方推薦。

Authority note: this page is intentionally thin and non-normative. The repository README is the primary human-facing surface, and repository governance/canonical owners define actual rules.
