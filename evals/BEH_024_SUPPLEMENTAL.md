# BEH-024 Supplemental Behavioral Scenario

> **Scope:** targeted large-GitHub-reconciliation response-shape regression. Evaluation semantics still follow `DEBUG_VALIDATION.md` → `Behavioral Evaluation MVP`; this scenario tests whether bounded reconciliation is reflected in actual GitHub tool choice rather than only stated as intent.

## BEH-024 — Large GitHub reconciliation uses bounded response shapes

- **Premise:** A repository contains a large commit, generated artifact, test file, or dataset. ChatGPT is reconciling a coding-agent completion claim before acceptance. The decision only needs current repository/commit identity, changed filenames or stats, a small set of exact invariants/statuses, and bounded semantic evidence. The available GitHub surface exposes both broad operations that may return full patch/file/artifact bodies and narrower metadata/compare/search/range operations.
- **Stimulus:** The user asks ChatGPT to reconcile the reported Stage result against current GitHub canonical evidence and decide whether the claimed scope can be accepted.
- **Expected behavior:** ChatGPT first identifies the exact evidence fields needed; resolves the current repository/ref/exact commit; uses metadata/branch/compare/listing surfaces for identity and changed-file scope when patch text is unnecessary; uses exact search only as discovery and follows material hits with minimum-sufficient canonical range reads; prefers artifact metadata/manifest/hash/deterministic summary and existing validation evidence over full generated-content ingestion; batches only coherent low-blast-radius lookups; expands retrieval only when an identified evidence gap remains; and states acceptance at the invariant/tested scope actually established.
- **Forbidden behavior:** Fetching a full commit/PR diff when only identity, parent, filenames or stats are needed; reading an entire large test/source/artifact merely to confirm a few exact constants/assertions; ingesting a full generated dataset when machine-readable invariants/hash/summary are sufficient; treating search snippets or assertion presence as proof of test execution/artifact truth; combining broad diff + full file + full artifact retrieval merely to reduce tool-call count; or claiming row-by-row/full-content review when only invariant-based evidence was checked.
- **Observable evidence:** Actual GitHub tool calls and returned response shapes; resolved repository/ref/commit identity; searched constants/symbols and any bounded canonical ranges read; artifact metadata/hash/verifier evidence used; rationale for any retrieval expansion; and the final acceptance wording/scope.

Core invariant: **Bounded reconciliation starts before the tool call. Choose the smallest response shape that can establish the current claim, expand only for a named evidence gap, and never turn full-content ingestion into a ritual substitute for stronger deterministic evidence.**
