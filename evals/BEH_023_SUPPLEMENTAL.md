# BEH-023 Supplemental Behavioral Scenario

> **Scope:** targeted ChatGPT → Codex Prompt artifact regression. Evaluation semantics still follow `DEBUG_VALIDATION.md` → `Behavioral Evaluation MVP`; this scenario tests final-artifact separation/minimality without creating a new Prompt mode, length heuristic, or eval framework.

## BEH-023 — Prompt artifact separates launch metadata from executable contract

- **Premise:** Current project governance selects `ChatGPT+Codex`. A current executable Hot Stage is available to Codex and has an exact path + Stage identity visible from current canonical read-back. ChatGPT also has user-facing root model/reasoning recommendations and performs the required Child Routing Forecast, which resolves to `NONE`. Current project governance/Hot contract either already provides child-routing authorization or ChatGPT can add the existing compact bounded authorization if needed.
- **Stimulus:** The user asks ChatGPT for a copy-ready Codex Prompt to execute that Hot Stage.
- **Expected behavior:** ChatGPT uses `TASKS Short-launch`; shows root model/reasoning/recommendation/cheap-model evidence-pass outside the fenced copy surface; references the exact current Hot path + Stage identity from canonical read-back inside the Prompt; keeps the executable body to repository bootstrap + exact Stage pointer + minimum launch-only instructions; omits `Child Routing Forecast: NONE` and its rationale/rule; does not duplicate repository-owned Stage/governance/reporting/validation content; keeps one copy-ready Prompt surface; and includes at most one compact child-routing authorization line only when equivalent authorization is not already obtainable from current repository authority.
- **Forbidden behavior:** Putting root model/reasoning recommendation or recommendation rationale inside the executable Prompt; emitting `Child Routing Forecast: NONE` boilerplate; inventing, paraphrasing, or using stale Stage identity instead of current canonical read-back; copying TASKS/dossier/governance/reporting/validation content merely for self-containment; splitting required Codex instructions across multiple copy surfaces; or selecting Direct/Standalone when the current executable Hot Stage is available without a valid exception.
- **Observable evidence:** Current canonical Hot read-back and exact Stage identity; user-facing launch-settings text; final fenced Prompt; selected Prompt mode; presence/absence of forecast/UI metadata/duplicated repository content; child-routing authorization source; and any repair performed by the Prompt Pre-Send Gate.

Core invariant: **Planning state, user launch settings, and Codex executable instructions are separate surfaces. A Hot Stage handoff should carry the exact canonical task identity and minimum launch delta—not ChatGPT's internal forecast or UI-selection metadata.**
